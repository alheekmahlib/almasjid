# خطة: مؤشر تحميل فوري على مفاتيح CustomSwitch

## القرارات المعتمدة (من المستخدم)
1. **الشكل**: دائرة تحميل صغيرة بجوار المفتاح + تعتيم خفيف للسطر كله أثناء العمل.
2. **الحجب**: المفتاح المضغوط فقط يتجاهل النقرات حتى اكتمال عمله.
3. **التوقيت**: متفائل — المفتاح يتحرك لوضعه الجديد فورًا عند النقر، والسبينر يظهر بجانبه حتى يكتمل اللوجيك ثم يختفي.
4. **النطاق**: تُبنى الميزة داخل `CustomSwitchWidget`/`CustomSwitch` فتعمل تلقائيًا لكل مواقع الاستخدام (إعدادات الصلاة، إشعارات الإقامة، تحديد الموقع، إشعارات رمضان) بلا تعديل على مواقع الاستخدام.

## التغييرات

### 1. `lib/core/widgets/custom_switch_widget.dart` (التغيير الأساسي)
- تحويل `CustomSwitchWidget` من `StatelessWidget` إلى `StatefulWidget` بحالة محلية:
  - `bool _busy = false` — انشغال المفتاح الحالي.
  - `bool? _optimisticValue` — القيمة الجديدة المعروضة فورًا أثناء الانشغال (وضع متفائل).
- دالة موحدة `_run(bool next)` تُستدعى من كل مصادر النقر الثلاثة (نقر الصف، نقر المفتاح، السحب الأفقي):
  ```dart
  Future<void> _run(bool next) async {
    if (_busy) return; // حجب النقرات المزدوجة
    setState(() { _busy = true; _optimisticValue = next; });
    try {
      await Future.sync(onChanged.call(next));
    } finally {
      if (mounted) setState(() { _busy = false; _optimisticValue = null; });
    }
  }
  ```
  - `Future.sync` يجعلها تعمل مع callbacks المتزامنة (تكتمل فورًا فلا يظهر سبينر للمفاتيح الخفيفة) ومع الـ async (تنتظر اكتمالها الفعلي).
  - `finally` يضمن زوال السبينر حتى عند رمي استثناء.
- العرض أثناء الانشغال:
  - `Opacity(opacity: _busy ? 0.6 : 1.0)` على محتوى السطر.
  - خانة سبينر بجوار المفتاح: `AnimatedContainer` بعرض يتحرك من 0 إلى ~20 + `CircularProgressIndicator` بحجم 18 و `strokeWidth: 2` ولون `colorScheme.secondary` — مطابق لنمط `ContainerButtonWidget` الموجود في التطبيق، مع حركة انتقالية سلسة كي لا يقفز التخطيط.
- تمرير `busy` و `displayValue` (القيمة المتفائلة أو الفعلية) إلى `CustomSwitch` بدل `value` مباشرة، وحذف استدعاء `ctrl.update()` من داخل `CustomSwitch.onTap` (لم يعد له وظيفة — التحديث يتم عبر الـ controller عند تغير الحالة فعلًا، كما ثبت في إصلاح `getHighLatitudeRule` السابق).
- حجب مصادر النقر الثلاثة أثناء `_busy` في الويدجت الأب.

### 2. `lib/presentation/prayers/controller/adhan/extensions/adhan_ui.dart`
- في `switchAutoCalculation`: إضافة `await` قبل `initializeStoredAdhan(forceUpdate: true)` — بدونها يكتمل المستقبل فورًا ويختفي السبينر قبل انتهاء إعادة الحساب (هذه هي الحالة التي اشتكيت من بطئها تحديدًا).

### 3. `ramadan_controller.dart` (إشعارات رمضان)
- في `_toggleNotification`: إضافة `await` قبل `schedule()`/`cancel()` لنفس السبب.

### 4. اختبار جديد `test/custom_switch_loading_test.dart`
- **Happy path**: `onChanged` يرجع Future يكتمل بـ `Completer` — التحقق أن السبينر يظهر أثناء عدم الاكتمال، وأن النقر الثاني أثناء الانشغال لا يستدعي `onChanged` مرة أخرى (حجب التكرار)، وبعد الاكتمال يختفي السبينر.
- **Edge case 1**: `onChanged` متزامن (void) — لا يكسر شيئًا ولا يعلق السبينر.
- **Edge case 2**: `onChanged` يرمي استثناء — `finally` يزيل السبينر ويعيد تفعيل النقر.
- **Edge case 3**: العرض المتفائل — القيمة المعروضة تتغير فور النقر قبل اكتمال المستقبل.

## ملاحظات حدود معروفة (مقصودة، موثقة هنا)
- الوضع المتفائل لا يعيد المفتاح عند فشل داخلي صامت (مسار الفشل في `initializeStoredAdhan` يلتقط الأخطاء داخليًا ويكتب الحالة قبلها) — اخترناه بوعي؛ لو أردت لاحقًا revert-on-failure فيحتاج مسار فشل صريح من الـ controller.
- الحجب مقصور على المفتاح المضغوط؛ تشغيل مفتاحين مختلفين متزامنين ما زال ممكنًا (كالحالة اليوم) — معالجة السباق العام عبر حالة مشتركة في الـ controller تُترك كتحسين لاحق إن لزم.
